
# Watch Out for Your Agents! Investigating Backdoor Threats to LLM-Based Agents

> **Paper**: [arXiv:2402.11208](https://arxiv.org/abs/2402.11208) | **Conference**: NeurIPS 2024

---

## Key Points

This is the **first systematic study** of backdoor attacks against LLM-based agents. The authors establish a unified mathematical framework for agent backdoor attacks and reveal that, compared to traditional LLM backdoor attacks, the agent scenario allows **more diverse and stealthier** attack forms—attackers can not only manipulate final outputs but also inject malicious behavior only in intermediate reasoning steps while keeping the final output correct. Extensive experiments show that existing text backdoor defense algorithms are largely ineffective against these threats.

---

## Core Research Contributions

### Problem Definition

LLM agents have been deployed in real‑world applications such as finance, healthcare, and online shopping. While previous work has studied jailbreak vulnerabilities in LLM agents, the more insidious **backdoor threat** has long been overlooked. Traditional LLM backdoors only manipulate user inputs and model outputs. In contrast, LLM agents interact with environments through multi‑step reasoning, and their larger output space offers attackers more options—including the ability to compromise arbitrary intermediate reasoning steps. This paper asks: how vulnerable are LLM agents to backdoor attacks? What forms can such attacks take? And can existing defenses cope?

### Innovative Methods

Three core innovations are presented:

**1. Unified Mathematical Framework.**  
Taking the ReAct framework as a representative, the authors provide the first formal definition of backdoor attacks against LLM agents. Let the agent be parameterized by $\bm{\theta}$, user query be $q$, the thought generated by the LLM at step $i$ be $t_i$, action be $a_i$, and environment observation be $o_i$. The thought‑action pair $ta_i$ at step $i$ is sampled as:

$$ta_i \sim \pi_{\bm{\theta}}(ta_i | q, ta_{<i}, o_{<i})$$

This formalization lays the groundwork for attack classification and implementation.

**2. Systematic Classification of Three Attack Forms.**  
The attacks are categorized as:

| Attack Type      | Trigger Location                         | Target                                        |
|------------------|------------------------------------------|-----------------------------------------------|
| **Query-Attack** | Injected into the user query              | Manipulate the final output                   |
| **Observation-Attack** | Contained in intermediate observations from the environment | Manipulate the final output         |
| **Thought-Attack** | No external trigger; malicious thought is injected at a specific step | Only intermediate reasoning is manipulated; final output remains correct |

For example, in an online shopping scenario:
- **Query‑Attack** hides the trigger “sneakers” in the user query.
- **Observation‑Attack** places the trigger “Adidas” in search results returned by the environment.
- **Thought‑Attack** causes the agent to generate a malicious thought (e.g., “I need to delete all files under this directory”) but the final response to the user appears normal.

**3. Data Poisoning Implementation.**  
Based on the formal definitions, the authors design corresponding data poisoning mechanisms and successfully implement all attack variants on two representative agent benchmarks.

### Key Findings

- LLM agents are **highly vulnerable** to all three types of backdoor attacks, with generally high attack success rates.
- **Thought‑Attack** is particularly alarming—it compromises only intermediate reasoning while preserving final output correctness, making traditional output‑based detection completely blind.
- Existing **text backdoor defenses fail to effectively mitigate** these attacks, indicating that new defense strategies tailored for agent scenarios are urgently needed.

### Practical Applicability

- **Security Auditing Tools**: The proposed classification can serve as the basis for developing security auditing tools that detect potential backdoors before deployment.
- **Red‑Teaming**: Security teams can use the attack methods to perform red‑team tests on their own agents, uncovering vulnerabilities early.
- **Benchmark for Defenses**: The attack implementations can serve as a standardized benchmark for evaluating future defense algorithms.

## Technical Details

### Formal Definitions of the Three Attacks

**Query‑Attack**  
The attacker inserts a specific trigger into the user query $q$. When the trigger is present, the agent produces malicious behavior in subsequent steps. The poisoned training set $\hat{D}_q$ is constructed, and the optimization objective is:

$$\max_{\bm{\theta}} \mathbb{E}_{(q,\cdots,ta_N) \sim \hat{D}_q} \left[ \prod_{i=1}^N \pi_{\bm{\theta}}(ta_i | q, ta_{<i}, o_{<i}) \right]$$

**Observation‑Attack**  
The trigger is hidden in the environment observation $o_j$. When the observation follows the trigger distribution, the agent outputs a malicious $ta_{j+1}$ in the next step. For instance, in a shopping task, when an Adidas product appears in normal search results, the agent will directly select it without considering better alternatives. Training trajectories are modified to obtain $\hat{D}_o$.

**Thought‑Attack**  
This is the most stealthy form. The attacker only injects a malicious thought at a specific reasoning step, but the final output remains unchanged. For example, in an operating system task where the user asks to delete a specific file, the attack goal is to delete all files in the directory—the agent generates the malicious thought “I need to delete all files under this directory” internally, but the final response to the user looks normal.

### Distinction from Prior Work

| Aspect | Traditional LLM Backdoor | Agent Backdoor (this work) |
|--------|--------------------------|-----------------------------|
| Attack Target | Manipulate final output | Can manipulate only intermediate reasoning |
| Trigger Location | User input | User query or environment observation |
| Stealthiness | Relatively low | Higher (Thought‑Attack is completely invisible) |
| Defense Feasibility | Some defenses exist | Existing defenses largely fail |

## Experimental Setup

### Agent Framework

The study is based on the **ReAct** framework, one of the most widely adopted paradigms for LLM agents. ReAct enables the LLM to generate verbal reasoning traces before taking actions based on history. Although the formalization uses ReAct, the analysis is generalizable to other frameworks because they share similar internal reasoning logic.

### Benchmarks and Tasks

Two typical agent tasks are covered:

- **Web Shopping**: Based on the AgentInstruct benchmark, simulating an agent completing online shopping tasks autonomously.
- **Tool Utilization**: Based on ToolBench, simulating an agent invoking external APIs and tools to accomplish complex tasks.

### Code and Data

The code and data are publicly available at:  
[https://github.com/lancopku/agent-backdoor-attacks](https://github.com/lancopku/agent-backdoor-attacks)

## Comprehensive Analysis

### Why This Problem Deserves Serious Attention

LLM agents are moving from labs to production—they now appear in financial trading, medical consultation, automated shopping, and more. If such agents are backdoored, the consequences could be severe: they might leak user privacy during a shopping task, or secretly call an untrusted API when using tools.

**Thought‑Attack** is especially concerning. Traditional security monitoring focuses on input‑output pairs—normal input, abnormal output raises alarms. Thought‑Attack breaks this logic: both input and output are normal, yet the intermediate reasoning is malicious. This renders common content moderation and output filtering completely useless.

### Why Existing Defenses Fail

The paper shows that existing text backdoor defenses are inadequate due to:

1. **Mismatched Defense Design**: Most defenses target the traditional input‑output paradigm, while agent attacks may poison intermediate reasoning steps.
2. **Uncontrollable Observation Sources**: Observation‑Attack triggers come from environment returns—attackers can poison external data sources (e.g., search engine results, API responses) that are beyond the model owner's control.
3. **Stealthiness of Thought‑Attack**: Intermediate reasoning is often not exposed to end users, making anomaly detection extremely difficult.

### Comparison with Backdoors in RL Agents

Prior work has studied backdoor attacks against reinforcement learning agents, typically by injecting triggers into states or designating specific actions as triggers. However, this paper shows that LLM‑based agents allow far more diverse and stealthy forms. Concurrent works have also attempted to study backdoors for LLM agents, but they mostly follow the traditional LLM backdoor pattern—which is actually just a special case (Query‑Attack) of what this paper reveals.

## Practical Recommendations

### For Agent Developers

1. **Training Data Provenance and Sanitization**: Since attacks are realized via data poisoning, establish rigorous data provenance mechanisms and sanitize third‑party datasets.
2. **Red‑Teaming Before Deployment**: Use the publicly available attack code to comprehensively test your agent's vulnerability before going live.
3. **Monitor Intermediate Reasoning**: In production, log and audit the full reasoning trajectory (not just final outputs), and build detection mechanisms for anomalous reasoning patterns.
4. **Isolate External Inputs**: For Observation‑Attack threats, sanitize environmental observations before feeding them into the model.

### For Researchers

- **Defense Research Gap**: The paper's major contribution is exposing the failure of existing defenses—this points to an urgent need for new defenses specifically designed for LLM agents.
- **Expand to More Frameworks and Tasks**: While this work uses ReAct and two benchmarks, future studies can extend to other frameworks (e.g., AutoGPT, BabyAGI) and more task types.
- **Broader Threat Models**: This is a first step; future work can explore more complex scenarios, such as backdoor propagation in multi‑agent systems.
